## 현재 목표와 다음 시작점

사용자는 내일 다른 컴퓨터에서 작업을 계속할 예정이다. 구현 코드와 필요한 캡처, 이 문서를 Git으로 함께 옮긴다. 채팅 기록 전체나 로컬 Obsidian 볼트 자체를 옮기는 것은 아니다.

현재까지 홈 피드 24개, 첫 네 상품 상세, 프레임 외부 인증동네 선택이 구현되었다. 최신 요청은 판매자의 목록·상세 위치 통일과 구 단위 선택이며 반영 완료했다. 다음 신규 화면은 아직 지정되지 않았다. 먼저 실행하고 사용자의 다음 요청을 받는다. 과거 범위 계산 논의를 다시 구현 차단 사유로 삼지 않는다.

실행은 README.md를 따른다. 새로운 컴퓨터에서 npm ci 및 실행은 별도로 확인해야 한다. 현재 데이터는 정적 fixture와 브라우저 상태로 구성되며 DB나 인증 서버가 없다.

## 확정한 개발 원칙

1. 당근 모바일 캡처를 먼저 재현하고 이후 기획대로 수정한다.
2. 홈 피드부터 화면 하나씩 진행한다. SEED 우선, 캡처 차이는 직접 개발한다.
3. 인증동네는 테스트 데이터 선택 기능이다. 실제 인증·GPS·범위 계산은 없다.
4. 목록과 상세의 판매자 위치를 동일한 판매자 데이터로 관리한다.
5. 선택은 구까지만 한다. 경기도 → 성남시 → 분당구이며 성남시만으로 적용할 수 없다.
6. 실제 가깝게/중간/멀게 범위 대신 **선택한 인증 구와 판매자 구의 ID 일치**로 바로구매 문의 UI를 정한다.
7. 수익 개선 기획을 캡처 재현에 임의로 섞지 않는다. 검수 구매·판매 대행·멤버십은 사용자가 기각했다.

## 지역 논의의 결론과 근거 구분

사용자 관찰: 따라큐의 어제 캡처는 강남구, 오늘 게시글은 분당구였다. 판매자 인증위치 변경에 따른 표시 변경일 수 있다는 가설이 있으나 실제 원인은 확인하지 않았다. 최초 목록의 강남 논현동과 상세의 분당구 불일치는 최신 요청에 따라 공통 판매자 지역인 분당구로 통일했다.

공식 도움말 확인 기록(2026-09-12):
- [먼 동네 바로구매 안내](https://cs.kr.karrotmarket.com/wv/faqs/28411?from_kind=instant_buy): 직거래 범위 밖 먼 동네 상품의 구매 전 채팅 제한을 설명한다. 정확한 범위 계산식까지 확인된 것은 아니다.
- [채팅없이 질문하기 안내](https://cs.kr.karrotmarket.com/wv/faqs/32267?from_kind=instant_buy): 질문 기능 조건 및 동네인증과 무관한 이용을 설명한다. 일반 채팅의 인증 요건까지 이 문서로 단정하지 않는다.

사용자 결정 D22/D23: 실제 범위 설정을 알고 있으나 이번에는 구 ID의 일치로 단순화한다. 이것을 실제 앱의 정책 검증 결과로 표현하지 않는다. 판매자 지역과 별도의 실제 거래 장소를 항상 동일하다고 일반화하지 않는다.

## 아직 구현하지 않은 범위

실제 인증, GPS, 거리 범위, 지역별 목록 필터, 서버 저장, 채팅방, 결제, 질문 전송, 신고·공유·키워드 알림 목적지, 나머지 홈 상품 상세는 구현하지 않았다. 화면에 있는 버튼이 후속 기능 완료를 의미하지 않는다. 실제 당근 API에 연결하지 않는다.

흐름: 상품 상세 → 어디로 보내드릴까요? 배송지 선택 → 바로구매 결제 화면. 배송지 화면의 닫기는 상품 상세로 돌아간다. 결제 화면은 사용자 최신 관찰에 따라 제목 없이 × 닫기만 표시하며 상품 상세로 돌아간다. 상태바와 Dynamic Island는 앱 콘텐츠 위에 유지한다.

결제 화면은 물품 금액, 택배비 3,600원, 구매자 보호 수수료 3.3%, 1.1% 할인, 당근 포인트, 최종 결제 금액을 구분한다. 캡처 상품 31,000원은 거래금액 35,623원, 할인 341원, 최종 35,282원으로 재현했다. 결제 실행은 범위에서 제외해 ‘물품 받고 돈 전달하기’ 버튼을 비활성으로 유지했다.

검증: 구현 전 기존안 바로구매 버튼 비활성 실패를 확인. 구현 후 정적 상품 배송지·결제·금액·뒤로가기·닫기·상태바, 기존안 작성 게시글 12,000원→15,864원, 신규 기획 정적 상세 비변경 확인. build, lint(오류 0·기존 Figma 경고 12), diff 검사 통과.

## 2026-09-16 — 최신 결제 화면 기존안·기획안 공통 적용
사용자가 당근 앱에서 새로 확인한 배송지·결제 캡처 3장을 제공했다. 앱 패치 여부는 확인하지 않았으므로 ‘패치됨’으로 확정하지 않고, 2026-09-16 사용자 직접 관찰의 최신 화면 참고로 기록한다. 원본은 프로젝트 루트의 KakaoTalk_20260916_checkout_address.jpg, KakaoTalk_20260916_checkout_payment_top.jpg, KakaoTalk_20260916_checkout_payment_amount.jpg에 보존했다.

배송지 화면은 뒤로가기, 주소 관리, ‘배송받을 주소를 선택해 주세요’, 기본주소 선택 카드, 주소 추가, 다음으로 재구성했다. 결제 화면은 × 닫기만 있는 상단, 배송지·상품·포인트·결제수단·현금영수증·결제 금액·포인트 적립 카드와 금액 결제하기 CTA로 재구성했다.

신규 캡처의 149,000원 물품은 구매자 보호 수수료 3,278원(2.2%), 배송비 3,600원, 최종 155,878원, 적립 779원이다. 프로토타입은 캡처 재현용으로 2.2% 계산을 적용한다. 기존 31,000원 상품은 수수료 682원, 최종 35,282원이다. 이전 O06~O07의 3.3% 수수료·1.1% 할인 화면은 과거 관찰로 남기되 현재 프로토타입 계산에는 사용하지 않는다.

기존안 정적·작성 게시글과 기획안 정적·복수 물품 게시글 모두 같은 배송지·결제 UI를 사용한다. 기획안은 상세에서 선택한 물품 합계를 넘기며 닫아도 선택을 유지한다. 실제 결제 완료는 구현하지 않아 최종 CTA는 비활성이다.

검증: 기존안·기획안 정적 상품 모두 배송지/결제 진입, 31,000원→수수료 682원→최종 35,282원, × 단독 헤더, CTA 문구 확인. 기획안 5,000원+8,000원 선택 시 2종·2개와 최종 16,886원 전달, 닫기 후 선택 유지 확인. build/diff 통과, lint 오류 0·기존 Figma 경고 12.

## 2026-09-16 — 결제 단계 슬라이드 인과 정적 채팅방

- 사용자 보고: 배송지→결제 전환에 오른쪽 애니메이션이 없었다. 원인은 상세가 결제 상태에서 언마운트되고 결제 단계가 섹션 교체만 하던 구조.
- 상세 섹션을 유지하고 결제·채팅을 형제 레이어로 렌더링(상세 `inert`). `CurrentDirectBuyFlow`는 배송지를 유지한 채 결제 섹션을 위에 겹치며 `.current-checkout`에 `detail-slide-in` 적용. 단계별 `useDialogControls`(Esc: 결제→배송지→닫기).
- 채팅하기: `src/screens/chat/ChatRoom.tsx`·`ChatRoom.css` 신규. 사용자 지시대로 구매자 “안녕하세요” → 판매자 “안녕하세요” → 구매자 “구매 가능할까요?”만 있는 정적 화면. 전송·저장 없음. 일반 거래·동일 시·도 바로구매·작성 게시글(내 글 제외)의 채팅하기가 연다.
- 검증: build·lint(앱 오류 0)·diff 통과. Chromium에서 따라큐 바로구매→배송지→결제 슬라이드 인, 상세·홈 푸시 유지, Esc 단계 복귀, 백본원 채팅방 열기/닫기 확인.
- 프레임 틈 보고: 사용자 정정대로 슬라이드 인 레이어가 왼쪽을 못 덮는 문제였다. 사용자 브라우저(Edge 151, DPR 2, 배율 0.937, 창 약 776×966)에서는 오버페인트만으로 부족해, `DeviceFrame.tsx` `fit()`이 프레임 위치를 계산해 화면 좌상단을 디바이스 픽셀 정수에 스냅하도록 바꿨다(`--device-left/top`, `transform-origin: 0 0`). 오버페인트 6px는 유지. 스냅만으로 소수 배율 5종의 직선 구간 틈이 사라졌고, 둘을 합치면 7개 창 크기에서 0. `--device-scale`이 소수일 때 레이어 왼쪽 경계와 프레임 클립 경계의 이중 안티에일리어싱으로 1 디바이스 픽셀 열이 반투명해져 밀린 홈이 비친다(DPR 2, 5개 창 크기에서 재현, 배율 1은 무관). `ProductDetail.css`에 `.product-detail, .chat-room, .write-sheet { box-shadow: 0 0 0 6px #16171b }`, `.current-checkout { … #000 }` 오버페인트를 넣어 모든 소수 배율에서 0으로 확인. 베젤은 12px 유지.
