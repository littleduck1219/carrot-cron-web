# RE:carrot 프로젝트 인계

갱신: 2026-09-12

기능 기준 커밋: `1a4cdda` — 홈 피드와 상품 상세 및 구 단위 지역 선택 구현

## 현재 목표와 다음 시작점

사용자는 내일 다른 컴퓨터에서 작업을 계속할 예정이다. 구현 코드와 필요한 캡처, 이 문서를 Git으로 함께 옮긴다. 채팅 기록 전체나 로컬 Obsidian 볼트 자체를 옮기는 것은 아니다.

현재까지 홈 피드 26개, 첫 두 상품 상세, 프레임 외부 인증동네 선택이 구현되었다. 최신 요청은 판매자의 목록·상세 위치 통일과 구 단위 선택이며 반영 완료했다. 다음 신규 화면은 아직 지정되지 않았다. 먼저 실행하고 사용자의 다음 요청을 받는다. 과거 범위 계산 논의를 다시 구현 차단 사유로 삼지 않는다.

실행은 README.md를 따른다. 새로운 컴퓨터에서 npm ci 및 실행은 별도로 확인해야 한다. 현재 데이터는 정적 fixture와 브라우저 상태로 구성되며 DB나 인증 서버가 없다.

## 확정한 개발 원칙

1. 당근 모바일 캡처를 먼저 재현하고 이후 기획대로 수정한다.
2. 홈 피드부터 화면 하나씩 진행한다. SEED 우선, 캡처 차이는 직접 개발한다.
3. 인증동네는 테스트 데이터 선택 기능이다. 실제 인증·GPS·범위 계산은 없다.
4. 목록과 상세의 판매자 위치를 동일한 판매자 데이터로 관리한다.
5. 선택은 구까지만 한다. 경기도 → 성남시 → 분당구이며 성남시만으로 적용할 수 없다.
6. 실제 가깝게/중간/멀게 범위 대신 **선택한 인증 구와 판매자 구의 ID 일치**로 바로구매 문의 UI를 정한다.
7. 수익 개선 기획을 캡처 재현에 임의로 섞지 않는다. 검수 구매·판매 대행·멤버십은 사용자가 기각했다.

## 지역 논의의 결론과 근거 구분

사용자 관찰: 따라큐의 어제 캡처는 강남구, 오늘 게시글은 분당구였다. 판매자 인증위치 변경에 따른 표시 변경일 수 있다는 가설이 있으나 실제 원인은 확인하지 않았다. 최초 목록의 강남 논현동과 상세의 분당구 불일치는 최신 요청에 따라 공통 판매자 지역인 분당구로 통일했다.

공식 도움말 확인 기록(2026-09-12):
- [먼 동네 바로구매 안내](https://cs.kr.karrotmarket.com/wv/faqs/28411?from_kind=instant_buy): 직거래 범위 밖 먼 동네 상품의 구매 전 채팅 제한을 설명한다. 정확한 범위 계산식까지 확인된 것은 아니다.
- [채팅없이 질문하기 안내](https://cs.kr.karrotmarket.com/wv/faqs/32267?from_kind=instant_buy): 질문 기능 조건 및 동네인증과 무관한 이용을 설명한다. 일반 채팅의 인증 요건까지 이 문서로 단정하지 않는다.

사용자 결정 D22/D23: 실제 범위 설정을 알고 있으나 이번에는 구 ID의 일치로 단순화한다. 이것을 실제 앱의 정책 검증 결과로 표현하지 않는다. 판매자 지역과 별도의 실제 거래 장소를 항상 동일하다고 일반화하지 않는다.

| 상품 | 판매자 | 목록·상세 공통 지역 | 현재 문의 동작 |
| --- | --- | --- | --- |
| 미개봉 백본원 | 라움 / raum | 서울특별시 관악구 / gwanak | 일반 상품이므로 기존 채팅하기 유지 |
| 아주 귀한 따라큐 | 두두 / dudu | 경기도 성남시 분당구 / bundang | 선택 구가 bundang이면 채팅하기, 다른 구면 질문하기 |

따라큐는 두 경우 모두 바로구매 버튼을 유지한다. 동일 구일 때 질문 패널을 숨기고 다른 구일 때 보여준다. 질문하기는 질문 영역으로 이동한다. 실제 채팅방·질문 전송·결제는 미구현이다.

지원 구는 서울특별시 관악구·서초구·강남구, 경기도 성남시 분당구 네 개다. gwanak/seocho/gangnam/bundang은 내부 키이며 공식 행정코드가 아니다. 서울은 cityId가 null, 분당구는 cityId가 seongnam이다.

관계: 홈 항목과 상품 상세의 sellerId → sellers → districtId → districts.
판매자 이름과 위치를 두 화면에 각각 하드코딩하지 않는다. 다른 홈 항목들은 아직 캡처 메타데이터를 사용하며, 상세를 추가할 때 공통 판매자 연결을 확장한다.

PrototypeUser는 schemaVersion 2, id, nickname, verifiedNeighborhoods, activeNeighborhoodId로 구성된다. 기본 사용자 id는 prototype-user-duck, 닉네임은 duck, 기본 선택은 gwanak이다. 네 지원 구는 모두 isVerified: true인 테스트 데이터다.

저장 키는 이전 데이터를 옮기기 위해 `re-carrot.prototype-user.v1`을 유지한다. 복원 시 bongcheon은 gwanak, seocho1은 seocho로 바꾼다. 기존 custom 이름은 유효한 구 이름/전체 경로 및 봉천동·서초1동만 정규화한다. 성남시만 저장됐거나 알 수 없는 값이면 기본 관악구로 돌아간다. 임의 하위 구를 추측하지 않는다.

브라우저 localStorage는 Git에 포함되지 않는다. 다른 컴퓨터에서는 기본 관악구이며, 따라큐에서 채팅하기를 확인하려면 외부 인증동네 선택기로 경기도 → 성남시 → 분당구를 적용한다.

## 구현된 화면과 상호작용

- 홈 26개: 최초 5개 + 추가 캡처 4장의 21개.
- 홈 첫 두 항목만 상세 경로에 연결된다.
- 해시 경로: /#/product/backbone, /#/product/mimikyu. 직접 상세로 진입해도 홈으로 돌아갈 수 있다.
- 홈은 상세 진입 중 숨겨진 상태로 유지하며 복귀 시 피드 스크롤을 복원한다.
- 상세는 고정 하단 버튼, 판매자, 본문, 지도 또는 바로구매 배너, 질문, 유사 상품, 판매자의 다른 상품, 광고 등을 재현했다.
- 사진 갤러리는 scroll-snap과 이전/다음·키보드 조작을 지원한다. 관심 상태는 로컬 화면 상호작용이다.
- 동네 선택 패널은 상위 지역을 바꾸면 하위를 초기화하고, 유효 구를 선택한 뒤 적용한다. Escape/외부 클릭으로 닫는다.
- 기존 스크롤바 숨김을 보존한다. 기본 다크 화면이며 테마 외부 컨트롤이 있다.

## 아직 구현하지 않은 범위

실제 인증, GPS, 거리 범위, 지역별 목록 필터, 서버 저장, 채팅방, 결제, 질문 전송, 신고·공유·키워드 알림 목적지, 나머지 홈 상품 상세는 구현하지 않았다. 화면에 있는 버튼이 후속 기능 완료를 의미하지 않는다. 실제 당근 API에 연결하지 않는다.

일반 이용자의 바로구매 상세부터 결제 직전까지가 기획 범위다. 커뮤니티·예약·좌석예매 목적지와 광고주 기능은 제외한다. 기존 채팅없이 질문하기·배송비 계산을 새 기능으로 제안하지 않는다.

- 브라우저에서 상위 지역 변경 시 하위 초기화, 성남시만으로 적용 불가, 분당구 적용 가능 확인.

다음 수정 후에는 영향을 받는 동작을 다시 확인한다. 특히 지역 변경 시 목록·상세가 같은 판매자 지역을 읽는지, 다른 컴퓨터의 빈 localStorage에서 정상 시작하는지 확인한다. UI 테스트 도구의 자동 스크롤이 홈 복귀 검증을 왜곡할 수 있으므로 실제 뒤로가기 동작으로 확인한다.
